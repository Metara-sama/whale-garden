# 谁在冲浪 · Live2D 冲浪测试器 v4

「鹈鹕骑自行车」的 Live2D 变体：下面那个模型横躺着当**冲浪板**，
上面那个模型踩着它冲浪，两个都能换成任意 Live2D 模型。

Live2D 做不了大幅肢体动画，所以整站的重心放在 **姿态 / 整体动画 / 海浪 / 粒子** 上。

- 默认模型来自 [sakiko.app](https://sakiko.app)，本地镜像 **2 个**（每个角色留一个：体积小 + 动作多）
- 也支持上传自己的模型：`.zip` / 选文件夹 / 贴 `.model3.json` 网址
- 支持**上传 BGM**，浪和水花实时跟着鼓点起伏

## 跑酷模式（DASH）

顶栏的 **▶** 不只是动画——点它会把这个页面原地切成跑酷游戏：

- **UI 无缝收起**：顶栏向上滑走、控制面板 `max-height` 收缩到 0，舞台自动从半屏扩到全屏（模型跟着重新布局，不是跳变）
- **当前角色直接变玩家**：你现在选的冲浪者 + 冲浪板就是游戏主角（缩放 0.46、站在水面基准线上）
- **沿用当前海况**：进场时用什么天就是什么天，游戏过程中每 18~30 秒自动换一次（HUD 右上角的图标会跳）
- **操作**：点屏幕 / ↑ / 空格 = 跳；向下滑 / ↓ = 下潜
- **障碍**：礁石、浮木、浮标（要跳）／海鸥、水母（要下潜）
- **结束**：角色被拍飞 + 水花 + 震屏 → 结算（分数 / 最佳 / 新纪录）
- **退出**：「继续摆弄」→ 面板滑回来，模型回到展示位置，海速复原

技术上它是独立文件 `game-mode.js`，挂在 `app.js` 之后，
通过 `window.__ride` 暴露的 `app / slots / scene / spawn / buildScene / layoutSlot` 接管渲染，
**完全没改 app.js**。两套互斥：

| | 展示模式 | 跑酷模式 |
| --- | --- | --- |
| 模型位置 | `layoutSlot()` 按 Y_RATIO 摆 | `applyModels()` 每帧覆盖（左 23.5%、水面 74%） |
| 海面速度 | `scene.speed` 用户设定 | 每帧写入 `18 + speed*34`（退出时复原） |
| 指针 | 拖模型 / 点模型播动作 | document 捕获阶段拦截，只做跳/潜 |

> 踩过的坑：`stage` 上的监听器和 app.js 是**同一个节点**，`stopPropagation` 拦不住同节点其他监听器，
> 必须把拦截提到 `document` 的捕获阶段，否则游戏中点屏幕会同时拖动模型。

### 手感参数（照 Chrome 小恐龙调的）

从 [wayou/t-rex-runner](https://github.com/wayou/t-rex-runner) 扒的原版配置：

```js
Runner.config = {
  GRAVITY: 0.6,              // px/frame²
  INITIAL_JUMP_VELOCITY: 12,
  SPEED: 6, MAX_SPEED: 13,   // px/frame
  GAP_COEFFICIENT: 0.6,
  MAX_OBSTACLE_LENGTH: 3,
};
Trex.config = {
  GRAVITY: 0.6, INIITAL_JUMP_VELOCITY: -10,
  HEIGHT: 47, HEIGHT_DUCK: 25,
};
// 障碍间距
minGap = Math.round(width * speed + typeConfig.minGap * 0.6)
gap    = random(minGap, minGap * 1.5)
```

换算到 60fps：

- 跳跃高度 `600²/(2×2160) = 83px` ≈ **1.77 倍恐龙身高**
- 滞空 `2×600/2160` = **0.556 秒**
- 速度 360 → 780 px/s
- 障碍间距 → **0.38 ~ 0.73 秒**
- 蹲下 = 碰撞盒高度 47→25（**变矮**，不是整体下沉）

本站照搬的比例：

| 项 | 小恐龙 | 本站实测 |
| --- | --- | --- |
| 滞空 | 0.556s | **0.68s** |
| 跳高 | 1.77× 身高 | **2.18× 身高**（0.34H） |
| 障碍间距 | 0.38~0.73s | **1.32~1.66s**（见下方公式） |
| 下潜 / 蹲 | 碰撞盒变矮 | **碰撞盒顶部下压 0.085H，底部不动** |


#### 间距/尺寸的两个关键修正

**间距必须按「时间预算」算，不能照搬像素公式**。小恐龙的仙人掌只有 17px 宽、通过玩家
0.047s，所以它敢用 0.48s 间隔；我们的浮木有 0.2×最短边 那么宽，通过要 0.32s。

```
最小间隔 = 滞空 0.68 + 最宽障碍通过 0.32 + 落地反应 0.32 = 1.32s
```

**障碍尺寸的宽/高基准必须分开**：宽度用 `min(W,H)`（保证横竖屏「通过时间」一致），
高度用 `H`（保证相对玩家身高的「跳跃余量」一致）。之前宽度用 `W`，横屏 880px 时礁石
变成 128px 宽的板砖、通过时间 0.49s 接近滞空，根本跳不过去。

#### 加速曲线（照小恐龙）

小恐龙：`SPEED 6 -> MAX_SPEED 13`，`ACCELERATION 0.001/帧 @60fps` -> 每秒 +0.06，
约 **117 秒**线性到顶（不是指数）。

这里映射成 `1 -> 2.4`，同样用 117 秒跑完：

```js
const SPD_MAX = 2.4;
const SPD_PER_SEC = (SPD_MAX - 1) / 117;   // 约 0.01197 / 秒
if (GM.speed < SPD_MAX) GM.speed += SPD_PER_SEC * dt;
```

实测：3s->1.038 / 6s->1.074 / 10s->1.121 / 15s->1.181 / 117s->2.40

相比原来 `1 + dist/7000`（28 秒到顶、前 10 秒就 +45%），现在前 30 秒只 +36%，
是那种“慢慢变快”的手感，而不是一上来就上强度。

#### 横屏时面板必须收宽度

横屏是 `flex-direction:row`，`#panel` 固定 `width:342px`。游戏模式原先只写了
`max-height:0`，结果高度收了、宽度还在 —— 舞台被挤成 880-342=538 宽。
改成 `max-width:0 + flex:0 0 0`，竖屏收高、横屏收宽，一套规则覆盖两个方向。

**下潜为什么不能再躲石头**：以前是「整组下沉 0.13H」，碰撞盒直接沉到石头下面去了；
现在改成「只把碰撞盒顶部往下压」，底部仍在水面下 → 礁石/浮木/浮标照样撞，只有悬空的
海鸥/水母能躲过。反过来，对海鸥**起跳**也会撞（跳起来正好顶到它），必须下潜。

## 交换逻辑：大小/角度属于"位置"，不属于模型

```
slot（位置，固定不动）           模型（跟着"谁站过来"走）
├─ 人位   y / fit / sc / rot     └─ model / rawW / rawH / name / preset
└─ 板位   y / fit / sc / rot
```

对调时**只把模型本身搬过去**，位置的 `sc / rot / ox / oy / flip / follow` 一概不动：

| | 交换前 | 交换后 |
| --- | --- | --- |
| **人位** | 高松灯，120%，60° | **千早爱音，120%，60°** |
| **板位** | 千早爱音，58%，35° | **高松灯，58%，35°** |

也就是说 —— **谁站到哪个位置，就用那个位置的参数**。

动画期间两者沿弧线互相飞过对方的位置、各转一整圈、中途两次水花；落定后身份互换。

## 10 个动画

全部走一个轻量 tween 系统（缓动 + 延迟 + 回调），动画期间按钮自动置灰，播完恢复。
**点动画按钮、点模型都不会弹气泡提示**（只有真出错才提示）。

| 按钮 | 效果 |

| 🔁 人和板对调 | 沿弧线互相飞过对方的位置、各转一整圈、中途两次水花 |
| 🌊 钻浪管 | 一道**卷浪**（浪壁 + 卷唇 + 管腔 + 泡沫）从右扫到左把模型吞掉 |
| 🤿 潜水 | 整体下沉 + 气泡上涌，2 秒后冲出水面 + 大水花 + 抖动 |

## 海面：每帧顶点位移的 Mesh，不是平移贴图

四层结构，每层都自带材质与动画：

```
天空（三段渐变 + 太阳 + 光晕 + 云 + 海平线雾带）
────────────────────────────────────────
远海   baseY = 地平线 + 2%        ← body mesh + 泡沫带 + 波峰高光线 + 滚动细节
中景   baseY = 地平线 + 32%       ← 同上（振幅更大）
[ 模型层 ]
近景   baseY = 地平线 + 62%       ← 同上（振幅最大、泡沫最厚）
[ 前景速度线 ]
```

每个水层 = **3 个 Mesh + 1 张滚动贴图**：

- `body` — 渐变纹理（顶端亮色 → 暗色），顶边顶点每帧跟着波形走
- `foam` — 泡沫带，紧贴波形线，横向平铺 + 顶部连续白边
- `slick` — 一条白色波峰高光线（最能体现"这是浪"）
- `TilingSprite` — 细波纹 + 泡沫点的细节贴图，横向滚动

波形 = **4 层不同频率的正弦叠加**（0.62 / 0.27 / 0.16 / 0.08），
每层频率、振幅、相位、流速都不同，还有缓慢的"潮位"起伏。

> 一开始我用 `Graphics` 每帧 `clear()` + 重画，实测单帧直接炸到 500ms。
> 换成 Mesh 顶点位移后，**单帧渲染 7–8ms**（约等于 120fps 的能力）。

## 性能

| 项 | 做法 |
| --- | --- |
| 水面 | Mesh 顶点位移（不是每帧重绘 Graphics） |
| 尺寸 | 缓存 `clientWidth/Height`，不每帧读（避免布局回流） |
| 粒子 | 固定池（上限 200），池满直接丢弃，不 splice 重排 |
| 音频 | 频谱每 3 帧分析一次 |
| 后台 | 页面切走自动停渲染，回来继续 |
| 省电模式 | 渲染分辨率降到 1x + 波浪顶点减半 |

> 注：无头 WebView 里 `requestAnimationFrame` 会被节流到 2fps，
> 所以别信那里的 FPS —— 用 `renderer.render()` 手动计时才准（实测 7–8ms/帧）。
