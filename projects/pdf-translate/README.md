# 🐋 文献翻译嵌字机（大肥鱼版）

PDF 文献进 → API 翻译 → **自动嵌字** → 译文 PDF 出。
API 只负责「翻译」这一件事，排版、擦原文、换行、字号自适应全部由本地脚本自动完成。

---

## 1. 启动

手机/电脑上进入本目录，起一个本地静态服务（`file://` 打不开 pdf.js 的 worker）：

```bash
cd /sdcard/Download/Operit/paper_translate
python3 -m http.server 8080
```

然后浏览器打开：**http://127.0.0.1:8080/**

> 也可以用 `sh serve.sh`（内容就是上面那条命令）。

## 2. 用法

1. **填 API**：Base URL / Key / 模型（任意 OpenAI 兼容接口，如 `https://api.deepseek.com/v1` + `deepseek-chat`，或硅基流动、中转站都行）。点「测试连接」确认可用。
2. **选 PDF**：填页范围（如 `1-6`，留空=全部），选渲染倍率（推荐 2.5×）和嵌字模式。
3. **点「▶ 一键跑完全流程」**：分析 → 翻译 → 嵌字渲染，进度条和日志会实时显示。
4. **检查结果**：每页左边是嵌好字的预览图（点开可放大），右边是逐块的「原文 / 译文」，**译文可以手改**，改完点该页的「重新嵌字」即可重排。
5. **点「4. 导出 PDF」**：生成 `原文件名_zh.pdf` 下载到浏览器下载目录。

## 3. 参数说明

| 参数 | 作用 |
|---|---|
| 并发请求 | 同时发几个翻译请求，2~3 比较稳，太高容易被限流 |
| 每批字符数 | 每次请求塞多少原文，1600 左右性价比最高 |
| 领域提示 | 填「有机化学」「Transformer 架构」之类，术语会更准 |
| 渲染倍率 | 导出清晰度。2.5× ≈ 180dpi，3× 更清晰但更慢更占内存 |
| 嵌字模式 | **替换原文**：擦掉原文写译文（推荐）；**双语**：原文保留，译文写在该块下方空隙里（空隙不够就跳过该块） |
| 译文字号系数 | 整体放大/缩小译文，1.0 是跟随原文字号 |
| 智能底色 | 从原文字块四周采样底色，保留灰底/色块，不会擦出白补丁 |
| 跳过公式与数字 | 字母占比过低的块（公式、表格数字）不翻译也不擦除，保留原样 |
| 允许向下利用空隙 | 译文超长时可借用下方空白，不容易挤成蚂蚁字 |
| 译文过短时自动放大 | 短译文自动放大铺满块宽，观感更整齐 |

## 4. 它怎么干活（原理）

```
PDF → pdf.js 提取文本层（每段文字的字号+坐标）
    → 行聚类（同基线合并，左右栏靠水平间距切开）
    → 栏间空隙检测（覆盖率直方图找中线，双栏/单栏自动判断）
    → 段落切块（行距+左边距判断，顺带修连字符断词）
    → 跳过公式/页码/表格碎片
    → 分批调 API（严格 JSON in / JSON out，失败自动降温重试，再失败逐条重试）
    → 逐页渲染成高清图：采样底色 → 擦掉原文 → 中文按块宽折行 → 字号自适应缩放
    → jsPDF 逐页拼回 PDF
```

## 5. 常见问题

- **PDF 打不开**：确认是用 `http://127.0.0.1:8080/` 打开而不是 `file://`。
- **一页都没翻译**：多半是**扫描版 PDF（图片型，没有文本层）**。本工具走文本层，扫描件需要先 OCR。
- **某块翻译失败**：日志会写「单条失败（保留原文）」，该块原样保留，也可手填译文后重新嵌字。
- **公式行被翻成乱码**：勾上「跳过公式与数字」；仍有个别没跳过的，把该块译文清空再重新嵌字即可。
- **导出很慢/内存吃紧**：调低渲染倍率，或分批（页范围填 `1-5`，导出，再 `6-10`）。

## 7. 目录

```
index.html          页面（UI + 配置）
js/pdfparse.js      文本层解析：行聚类 / 分栏 / 段落切块 / 跳过规则
js/translate.js     批量翻译（OpenAI 兼容），分批+并发+重试
js/render.js        嵌字引擎：底色采样 / 折行 / 字号自适应 / 绘制
js/app.js           主流程与界面逻辑
lib/                pdf.js 3.11 + jsPDF 2.5（本地自托管，不依赖 CDN）
test/               离线测试脚本
```
